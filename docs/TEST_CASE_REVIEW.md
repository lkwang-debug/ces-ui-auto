# CES UI 自动化用例评审记录

## 本轮结论

- 所有已收集用例均通过统一的 Allure 中文模块和用例标题映射；pytest 节点名保持不变，因此仍可用 `文件.py::test_函数名` 精确执行。
- 数据管理已完成真实闭环：下载已有 SQL/DMP、上传同内容的唯一副本、识别服务端重命名后的新记录，并删除该记录。
- 服务器列表新增了会议服务器和录制服务器的字段校验、创建、修改、查询、删除用例。4.39.7 的新增入口为服务器分类后的 “+” 卡片，而非文字按钮；两类服务器均作为普通回归实际执行，并在用例结束后删除本次创建的数据。

## 当前环境能力差异

在 `192.168.7.185:28080` 的 4.39.7 实测服务器列表中，选择“会议服务器”或“录制服务器”分类后，服务器卡片区域末尾的 “+” 卡片可打开“新增服务器”弹窗。会议服务器类型可在下拉中选择；录制服务器弹窗默认显示“资源平台服务器”，该版本不以标准选项列表暴露它，因此用例保留并验证该页面默认值。

会议服务器、录制服务器的参数校验与 CRUD 均不是高风险用例。所有成功路径使用唯一设备 ID 和 `uiauto_` 名称，fixture 在结束时按该唯一 ID 删除测试数据。

终端管理页在当前 4.39.7 环境中可显示分页下拉选项，但选择页大小不会写回当前值。这是页面版本行为，不属于可由 UI 自动化绕过的前置条件。自动化覆盖下拉可达性与候选值，不将“已修改并持久化”列为本版本通过项。

## 审计规则

1. 业务测试必须同时具有操作和可观察结果，不能以页面非空、对象非空或 `assert True` 作为成功依据。
2. 创建型测试必须使用唯一标识，并在 fixture 或 `finally` 中只清理本次数据。
3. 下载必须验证文件存在、扩展名和大小；可定位的业务文件还要验证目标记录。
4. 环境前置数据缺失在开发模式明确跳过，在 `ACCEPTANCE_MODE=True` 时失败；产品不支持的功能不得伪造通过。
5. 仅恢复备份、服务器启停和结束在线会议保留 `destructive` 标记，默认 `run.py` 不执行。

## 尚未自动化的能力

- 用户导入与终端导入目前覆盖导入入口、覆盖选项、官方模板下载、运行时工作簿生成和导出文件；尚未提交工作簿到服务端并验证“不覆盖/覆盖/混合导入”四种结果。现有用例标题没有将其标记为“真实导入”，正式验收前需要补充专用测试数据及该闭环。
