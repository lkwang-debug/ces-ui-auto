# 稳定性改造对照

最终状态以独立全量报告与 `.stability/acceptance.json` 为准。本清单说明改动与证据要求，不表示验收已完成。

| 原问题 | 修正 | 保留的业务证据 |
| --- | --- | --- |
| SDK/API 菜单改名使共享前置失败，几十条用例连带报错 | 按功能 ID、版本及真实授权别名解析；未登记菜单由独立审计项报告 | 真实点击、路由、页面专属控件；新菜单不冒充已覆盖业务 |
| 终端新增“可见状态”筛选后，按下标误选搜索类型 | 使用搜索字段标签与下拉所属控件定位 | 创建目标、准确搜索、刷新、修改及精确删除 |
| 会议表格嵌套按钮导致“修改”点击“授权” | 从目标行的实际文本、标题或 tooltip 判断动作含义 | 不以按钮位置代替动作；修改前后值及刷新持久化 |
| 日志用户名硬编码 admin，与 sysmanager 登录不符 | 使用当前配置身份，真实写入并验证日期提交 | 用户名、时间范围和组合结果匹配，清空恢复 |
| Ant Design 隐藏的辅助选项被当成可点击选项 | 验证尺寸及实际命中元素 | 页大小与页码变化，实际新请求完成 |
| 弹窗重绘使错误提示丢失、元素失效 | 活动表单内一次性读取字段与错误；等待提交后的稳定状态 | 目标字段具体错误，不接受任意错误或上一条 toast |
| 删除后空表被当成“页面未就绪” | 页面结构就绪与业务数据是否为空分开判断 | 本次查询请求完成后，目标准确记录不存在 |
| 上一模块下载目录、历史文件污染后续用例 | 每次下载单独目录及事件证据；失败分支恢复默认目录 | 新文件、完成状态、扩展名、大小和格式/内容 |
| CRUD 共用一份可变数据，依赖执行顺序 | 每个修改/删除/查询节点独立创建；登记原名和改名 | 原有节点保留，乱序与单独执行，准确清理与不存在断言 |
| 会议详情随机取第一行，入口依授权/数据不同 | 固定会议室及开始时间，四种入口都限定同一条真实记录 | 签到、投票、智能纪要、文字转写各自真实弹层 |
| CES 页面已从 ClientID 改为 Key/Secret | SDK 与服务端 API 分别识别表头、查询动作及弹窗字段 | 标识与列表一致、Secret 存在；附件不打印 Secret |
| 一套 AI 模型失败阻断其他模型 | 三套模型独立执行；失败后附上游只读诊断 | 新增、改名、刷新、UI 连通性、默认值恢复、准确删除；诊断不代替 UI 断言 |
| 改密重复启动 Chrome、无条件管理员重置 | 固定隔离验证会话；通过个人资料恢复；仅复用已验证原密码的前置身份 | 新密码真实重新登录、原密码恢复后重新登录；非法密码具体字段错误及原密码仍有效 |
| 登录用户读取可能回退成输入期望值 | 读取两版真实 `.hst-user-name`，认证后核对实际账号 | 真实页面账号、后台控件；缺失或不匹配即失败 |
| 编辑弹窗姓名非空就开始填，可能使用重绘前数据 | 等待本次 `userEdit` 请求、准确目标用户名及表单稳定 | 400ms 延迟加载故障测试；刷新后的昵称、手机号匹配 |
| 组织修改只等待弹窗出现，未确认编辑数据回填 | 等待本次 `departEdit`、原部门名称准确加载，再按字段标签填写；无标签的组织按钮只接受实测 `.dept-oper` 两按钮结构，结构变化则失败 | 修改和取消仍独立；保存后新名称可查询、旧名称不存在；失败在清理前记录阶段、字段和截图；登记及清理结果单独附件 |
| 终端修改未等待原字段回填；同名定位方法重复定义 | 读取目标行名称、序列号并等待表单两项一致；移除重复定义，按编辑图标定位 | 原生输入稳定后才保存；刷新后查询新名称；取消验证旧名称存在且新名称不存在 |
| 旧版日期确认是链接，移动区间可能出现中间非法范围 | 支持真实确认链接；组合筛选先清空旧条件再重填 | 新旧版日期、用户名结果匹配及三个实际字段清空 |
| 同一页反复完整布局等待 | 只复用同一文档和组件的表头、组织树就绪状态 | 不缓存行数据；查询仍等本次接口、成功状态、登录状态和表格稳定 |
| 已识别汉字验证仍等待旧验证码 | 直接分派已识别状态；每次非末次点击等待序号标记 | 保留真实鼠标、坐标换算、错误顺序、双分辨率、三十张样本及连续登录 |
| 失败后弹窗遮挡下一用例 | 用例结束只执行取消/关闭；无法关闭则明确失败 | 不点保存/确认，故障注入后下一操作仍可执行 |
| 授权弹窗只点击关闭就清空列表条件，关闭动画中的 wrapper 仍拦截点击 | 授权保存、重新打开核验后等待内容和遮罩关闭；用户、终端、组织、会议室查询先校验真实点击命中 | 不穿透遮罩；拒绝查询仍被阻挡的控件；保留原生滚动，透明且不接收点击的残留层不误报 |
| 登录测试改变了管理浏览器身份，同账号认证可能使另一会话失效 | 登录与改密统一在验证浏览器；管理浏览器在后续业务开始前按需重新认证 | 登录失败后用户修改通过；管理员改密恢复后用户查询通过 |
| 通知时间字段瞬时不可见、只读控件被强行改属性，且时间被截断 | 等待活动通知表单；使用真实日期控件；前置就绪后生成当前后一分钟的完整时间 | 新旧版均真实保存通知并确认邮件全部发送成功；失败时保留活动表单和留样信息 |
| 多轮结果被覆盖或混入重跑结果 | 每轮独立目录及代码/有效配置摘要，根因与原始结果同时保存 | 三轮相同节点、相同配置、相同结果，失败证据不改判 |
| 静态断言清单把代码中的默认密码字面量复制进 manifest | 源码指纹继续计算原始字节，导出的断言及操作元数据递归脱敏 | 敏感值不进入清单；原始源码变化仍改变指纹；用例状态和断言数量不变 |

## 断言核对范围

| 功能 | 必需保留 |
| --- | --- |
| 新增、修改 | 保存反馈、目标查询、字段匹配、刷新持久化 |
| 删除、清理 | 确认完成、新查询完成、精确目标不存在 |
| 搜索、清空 | 实际输入、结果匹配、字段与列表恢复 |
| 非法输入 | 特定目标字段错误、拒绝保存、没有产生本次记录 |
| 取消 | 弹窗关闭、列表及业务值没有改变 |
| 导入 | 实际上传、覆盖选项、后台结果、目标查询；终端实际导入仍明确排除 |
| 下载 | 本次新文件完成、格式与有效内容；历史文件不能满足 |
| 配置与改密 | 原值记录、修改持久化、原值/原密码恢复并验证 |

节点核对使用修改前保存的 293 个 Allure 结果逐项比对最终结果键；新增菜单审计及两个可达性节点、两套独立 AI 模型增加节点。操作与断言的静态清单由验收脚本生成在 `.stability/coverage-audit.md`。修改前没有完整源码快照，因此该清单不能替代逐个业务证据审阅，也不声称做过原源码断言逐字一致比较。
